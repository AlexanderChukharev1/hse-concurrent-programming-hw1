# Задание 1. Бронирование мест

## Мониторы и защищаемые данные

| Монитор | Что защищает                                                                                            |
|---|---------------------------------------------------------------------------------------------------------|
| Каждый внутренний `SeatState` | Состояние конкретного места (свободно, забронировано или продано и список ожидающих потоков)            |
| `lifecycle` | Счётчик бронирований `nextId`, список ожидающих `waiting` и согласование операций с остановкой сервиса. |
| `schedule` | Очередь истечения броней `expirations` и работу фонового потока.                                        |
| Каждый внутренний `Waiter` | Флаг `signaled` и ожидание потока, который вызвал `holdOrWait`.                                         |

Флаг `stopped` объявлен `volatile`, поэтому все потоки видят изменения его значения.

Поле `Waiter.registered` и объект `Deadline` используются только одним потоком, поэтому синхронизация для них не требуется.

## Почему невозможна взаимоблокировка

Мониторы мест всегда захватываются по возрастанию индексов, поэтому не может возникнуть ситуация, когда два потока ждут освобождения мониторов друг друга.

При ожидании в `holdOrWait` мониторы мест не удерживаются. Фоновый поток освобождает `schedule` перед захватом мест. `shutdown` освобождает `lifecycle` перед пробуждением потоков и вызовом `join`.

Мониторы `lifecycle` и `schedule` захватываются в установленном порядке (`lifecycle` до `schedule`).
